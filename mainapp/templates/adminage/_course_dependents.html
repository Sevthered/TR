{% comment %} The dependent half of the course cascade: Nivel and Sección. Rendered two ways, and only ever from views.course_cascade_context() — inlined by assign_subjects.html on the first paint, and returned whole by load_course_sections for the htmx swap. One renderer, so the option text cannot drift between the two; mainapp/_trimester_options.html states the same rule for the trimester cascade, where a mismatch would silently rename every option the moment a parent select changed. Both selects are real controls inside the page's GET form, and that form's submit button is the path that always works. htmx only saves the round trip; with JavaScript off you pick a type, submit, pick a level, submit. Nothing here is a control that does nothing without scripting. The level select carries its own hx attributes even though the page could have held them, because it lives *inside* the swapped content: htmx processes what it swaps in, so they keep working after a replacement, but they have to travel with it. The whole block is one swap target rather than two option lists, because changing the type must repopulate Nivel *and* clear Sección — two targets, and htmx allows one hx-target per element. See load_course_sections. {% endcomment %}
