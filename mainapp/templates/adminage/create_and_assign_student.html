This was the app's only light-themed page — #f4f4f4 body, white card, drop shadow — and the only admin page that actually rendered its English {{ title }}, at both and <h1>. Both are gone: the app is dark and Spanish. "Name"/"Email" came from the CapitalCase model fields with no labels override, so the Spanish now lives in StudentCreationForm.LABELS where Django can reach it. The three-select cascade is gone, and that is the substantive change rather than the chrome. It was Tipo -> Nivel -> Sección over jQuery and load_course_sections, plus a hidden #hidden_course_id the script kept in sync and a submit button that started `disabled` and was enabled only by a change handler. With behaviors.js deleted and the CSP forbidding inline handlers, every one of those parts had to be rebuilt or dropped. Dropped, because the cascade cannot be made to work before JavaScript does on *this* page. assign_subjects can fall back to submitting its filter bar as a GET and re-rendering; this page is a single POST form, so any GET round trip would either discard the name and e-mail already typed or put a student's personal data in the query string. One grouped select over the year's sections needs no round trip at all — so there is nothing to degrade, no hidden field to keep in sync, and no disabled button. The select carries `name="course_id"` directly, which is the name the view already reads. The submit button is no longer disabled at all.
